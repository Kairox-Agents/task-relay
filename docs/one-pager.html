✅ Decisions — All Resolved

Who is v1 for?
Solo user, own machines
Philip's MacBook Pro on Tailscale. Making it available to his agent fleet. No multi-tenant complexity.
Network
Tailscale only, locked down
All machines already on Tailscale. No public endpoints, no NAT traversal. Tailscale ACLs for access control layer.
Language
TypeScript / Node.js
Best ecosystem for agent tooling. Native integration with Claude Code CLI. npm distribution.
Task intake
REST API + MCP Server
REST is the core transport. MCP server is a thin adapter for native agent tool discovery. Best of both worlds.
Isolation
Docker (default) + Host (opt-in)
Docker for safe defaults. Host mode for trusted agents on own machine. Configurable per-task.
Concurrency
1 concurrent agent task
Start simple. Avoid premature optimization. Queue handles overflow. Can increase later.
Browser automation
Browserbase + Firecrawl (v1.1)
Zero local risk for non-clean machines. Playwright as last resort in v2. Skip in v1.0 to ship faster.
License
BSL 1.1 (3-year change)
Individuals: full freedom. SaaS/commercial: needs license. Converts to Apache 2.0 after 3 years. Same model as MariaDB, Sentry.
Auth
API key over Tailscale
Tailscale = network auth. API key = app auth. Simple, honest, documented trust boundaries.
Coordination
Linear plugin (v1.1)
Core is task-in → result-out. Linear is a plugin: creates tickets, updates on completion. Zero core changes needed via webhook/callback hooks.

🔐 Isolation Model

Docker by default, host mode for trusted agents. Configurable per-task.

🐳 Docker Mode

DEFAULT
  • Container per task, mounted workspace only
  • No host filesystem access
  • network: none by default (no outbound)
  • ~2-3s cold start (negligible vs LLM call time)
  • Safe for third-party / untrusted agents
  • Requires Docker installed on host
  • Slight overhead on resource-constrained machines

🖥 Host Mode

OPT-IN
  • Zero overhead — subprocess directly on machine
  • Full access to local tools, env, filesystem
  • Best experience for your own agents
  • No Docker dependency
  • Agent can read/write anything user can
  • Only use with agents you fully trust
  • Codex -s workspace-write adds partial sandbox

📡 Task Intake Protocol

🔌

REST API + MCP Server (both)

REST as core — POST /tasks, GET /tasks/:id, SSE for streaming. Any HTTP client works. MCP as adapter — JSON-RPC over stdio, maps 1:1 to REST. Agents get native tool discovery.

MCP is low-cost to add and gets you agent-native integration with almost zero extra work.

📊 Log Backup

INCREMENTAL
  • Runs every N minutes (configurable, default: 15min)
  • Uploads new/changed task logs since last backup
  • NDJSON format: one event per line, easy to query
  • Low bandwidth — only deltas uploaded
  • Path: s3://bucket/task-relay/logs/{date}/

🗄 Full Backup

PERIODIC
  • Runs daily (configurable, default: 2am local)
  • SQLite DB snapshot + all task artifacts
  • Compressed tar.gz upload
  • Rotation: keep last N backups (default: 30)
  • Path: s3://bucket/task-relay/backups/{date}.tar.gz
  • Restore: download + extract + restart daemon

🔍 Claude Code Traces

PER-TASK
  • Deterministic path: ~/.claude/projects/{cwd-dashed}/{task_id}.jsonl
  • Uses --session-id {task_id} flag on claude -p
  • Full conversation: prompts, tool calls, edits, errors
  • Copied to S3 after each task completes
  • Debug file also copied: ~/.claude/debug/{task_id}.txt
  • Do NOT use --no-session-persistence — prevents transcript creation
  • OTel export available (v1.1): traces, metrics, events

⚠️ Risks

!

RCE is the product

This tool literally executes remote commands. V1 must be honest about what it protects against (Tailscale + API key + Docker) and what it doesn't.

!

Agent CLI quirks

Claude Code and Codex have different interfaces, streaming formats, and gotchas (e.g., nested claude -p produces empty output). Per-tool adapters needed.

!

Scope creep

"Agent fleet" thinking → scheduling, service discovery, load balancing. Not v1. Stay focused: one daemon, one machine, task in → result out.
